# Local Development Accounts

These seeded accounts exist only in a local Supabase database created with
`supabase db reset`. The seed runs after migrations from `supabase/seed.sql`.
Staging and production deployments do not run this file.

password listed below. Password hashes are generated by PostgreSQL with bcrypt
while seeding `auth.users`; plaintext passwords are not stored in application

## Expected Access

Assignments come from `role_definitions`, `user_roles`, `permissions`, and
`role_permissions`. Route visibility is a convenience; table policies remain
the data boundary. Department, college, course, student assignment, and
ownership constraints still apply to each permitted action.

| Role | Representative allowed action | Representative denied action |
|---|---|---|
| Rector | Manage colleges and departments within university scope | Read invoices without `finance.read` |
| Dean | Manage departments within the assigned college | Manage a different college's scoped resources |
| Department head | Manage courses and schedules in the assigned department | Manage another department's course |
| Professor | Manage grades and attendance for taught courses | Read or write unrelated course records |
| Teaching assistant | Manage attendance for assigned courses | Manage grades or unrelated courses |
| Registrar officer | Review/manage registration in permitted scope | Manage courses or grades |
| Academic advisor | Read assigned advisees' academic records | Read unassigned students' private records |
| Regular student | Read own grades, attendance, and invoices | Read another student's records or manage staff data |
| Freshman | Read own scoped academic information and course catalog | Read another student's records or staff workflows |
| Guest | Authenticate and access only explicitly public/basic areas | Directory, grades, attendance, invoices, registration, private files, roles, or administration |

The guest seed intentionally includes `role=rector` in editable user metadata.
The database signup trigger ignores that claim and assigns `guest`; the fixture
keeps this adversarial case visible for local security review.
